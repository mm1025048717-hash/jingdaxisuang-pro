## 政策与行业背景

### 1、总书记关于就业的重要论述

习近平总书记在 2024 年 5 月 27 日中共中央政治局第十四次集体学习时强调，**「就业是最基本的民生」**，事关人民群众切身利益、经济社会健康发展和国家长治久安。总书记指出，**「促进高质量充分就业，是新时代新征程就业工作的新定位、新使命」**，要把就业作为民生头等大事来抓。

总书记特别强调要**加强灵活就业和新就业形态劳动者权益保障**，主要包括：健全劳动法律法规，规范新就业形态劳动基准；完善社会保障体系，维护劳动者合法权益；扩大职业伤害保障试点，及时总结经验、形成制度；加强市场监管和劳动保障监察执法，有效治理就业歧视、欠薪欠保等乱象。

### 2、就业优先战略与灵活就业政策

2024 年 9 月，中共中央、国务院发布《关于实施就业优先战略促进高质量充分就业的意见》，将**高质量充分就业**作为经济社会发展优先目标。政策明确支持发展新业态新模式，推动数字经济、绿色产业等领域就业发展，**拓展数字经济就业新空间**，做好数字转型中的岗位挖潜、职业转换。

在灵活就业方面，国家健全灵活就业人员、农民工、新就业形态人员社保制度，全面取消在就业地参保户籍限制，扩大失业、工伤、生育保险覆盖面；出台《新就业形态劳动者休息和劳动报酬权益保障指引》等文件，规范平台用工。根据国务院报告，我国灵活就业人员规模已超过 **2 亿人**，新就业形态人员达 **8400 万人**（含网约配送员、网约车驾驶员等）；职业伤害保障试点已覆盖 2300 余万人参保。

### 3、与精打细算项目的契合

精打细算 Pro 面向灵活就业者、大学生副业、债务压力人群等群体，提供生存规划与机会聚合服务，有助于**提升就业匹配效率**、**缩短信息差**、**增强劳动者获得感**。产品形态符合「拓展数字经济就业新空间」的政策方向，与总书记强调的促进高质量充分就业、保障灵活就业者权益的部署相契合，具有良好的政策环境与发展前景。

## 一、技术可行性分析

### 1、项目名称与核心定位

**精打细算 Pro（Poor Man's Advisor Pro）**——面向普通人的 AI 智能管钱助手

**核心定位**：不只「度过危机」，更是**「从危机到致富的陪伴者」**。聚焦「帮普通人管钱」这一垂直场景，随用户从钱紧→稳定→有积蓄的不同阶段，提供对应价值，延长用户生命周期，实现老用户留存。

### 2、项目主要技术内容及基础原理、创新点、技术水平、技术指标、用途及应用范围

**技术内容：**

- **前端技术栈**：原生 HTML5、CSS3、JavaScript（ES6+），采用 PWA 架构，支持离线使用与桌面安装
- **AI 集成**：基于 DeepSeek 大语言模型（V3 输入约 2 元/百万 token，输出约 8 元/百万 token；支持硬盘缓存进一步降本），采用 OpenAI 兼容的 Function Calling（Tool Calling）协议，实现多技能智能调度
- **规则引擎**：本地 JavaScript 规则引擎，实现生存天数计算、日预算、账单提醒、债务风险评估等核心算法
- **机会聚合**：后端实时聚合 API 对接实习僧、聚合数据、58同城等开放平台获取真实招聘/兼职数据；未配置 API 时降级为 AI 生成 + 本地兜底数据（含 30+ 平台入口链接及热搜评论挖掘策略）

**基础原理：**

- 用户录入资金、支出、收入、债务、技能等数据后，规则引擎实时计算：可用资金、月支出、生存天数、危险等级、日预算、距发薪天数
- AI Agent 根据用户意图自动调用 12 项技能（财务分析、机会搜索、记账、预算、账单、谈判话术、技能学习计划、记忆存储等），返回可执行方案
- 机会雷达优先请求后端 `/api/opportunities/search` 获取实习僧等开放平台实时数据；未配置 API Key 时降级为 AI 生成或本地兜底（技能匹配、平台入口链接），支持自然语言对话式搜索

**创新点：**

1. **生存导向设计**：不只计算「还能活几天」，更输出「这几天怎么活」——每日可执行任务清单、最低成本食谱、协商话术等
2. **全周期陪伴**：从危机→稳定→积累，同一产品持续服务；避免「度过危机即流失」的单次工具陷阱，延长用户生命周期
3. **技能匹配推荐**：根据用户技能标签（开车、设计、剪辑、写作等）精准匹配兼职/零工/变现机会
4. **热搜评论挖掘**：AI 策略层从微博热搜、抖音热榜、小红书爆文评论区提取需求信号（基于大模型知识，非爬虫）；数据源优先对接开放 API 获取真实岗位
5. **本地优先 + 隐私安全**：数据存储在 localStorage，不依赖后端服务器，无账号体系也可使用

**产品原型与在线体验：**

本计划书**页面顶部**提供高保真产品原型（手机框内可交互）；在线正式版已部署于 [jingdaxisuang-pro.vercel.app](https://jingdaxisuang-pro.vercel.app/)。核心功能包括：生存概览、AI 军师（12 项技能）、机会雷达、登录与云端同步等，均可直接体验。

**技术水平：**

- 符合主流 Web 标准，兼容 iOS Safari、Android Chrome，支持 PWA 安装
- 大模型 Function Calling 调度成熟，支持多工具链式调用
- 规则引擎实现完整的财务建模与风险分级

**技术指标：**

| 指标 | 目标值 |
|------|--------|
| 首屏加载 | < 3s |
| 离线可用 | 核心计算、规则引擎全离线 |
| AI 响应 | < 30s（视 API 延迟） |
| 支持平台 | 58、BOSS、闲鱼、美团、猪八戒等 30+ |

**用途及应用范围：**

- **个人**：经济困难期的生存规划、债务应对、兼职/副业推荐、省钱方案；债务缓解后的记账、预算、储蓄习惯养成；有积蓄后的目标储蓄与简单理财意识
- **社工/公益**：辅助低收入群体进行财务自检与行动指导
- **教育**：财商教育、生存技能教学的辅助工具

### 3、与项目研究开发内容相关的国内外现状及发展趋势

**国内现状：**

- **记账类 App**：易观千帆 2021Q4 数据显示，随手记 MAU 约 1705 万人、鲨鱼记账 1074 万人，形成明显头部集聚；叨叨记账、挖财、51 信用卡管家等处于第三梯队。行业侧重点为消费记录与预算追踪，缺少「生存天数」「危险等级」「可执行行动清单」等生存导向功能。
- **兼职/招聘平台**：2024 年中国网络招聘行业规模约 183 亿元；BOSS 直聘、前程无忧、智联招聘为一梯队；58 同城、斗米、兼职猫等为兼职细分主力。平台以信息展示为主，缺乏基于个人财务状况、技能画像的智能匹配与跨平台聚合。

**国外现状：**

- **美国**：Mint 为最受欢迎的免费预算应用，支持账户同步、净资产、月度预算、账单提醒；Truebill（现 Rocket Money）主打订阅管理与债务优化；Cleo 提供智能聊天机器人与幽默反馈；Pocket Guard 含债务清偿计划；Plum 可自动储蓄。
- **英国**：MoneyHelper 为政府支持的免费财务建议工具，面向大众提供预算、债务、福利等指导。
- **共同短板**：海外产品聚焦「记账+预算+账户同步」，少有将「生存天数计算 + 可执行任务 + 跨平台赚钱机会聚合」整合，且多依赖银行账户对接，对无账户、低收入、临时就业场景覆盖不足。

**发展趋势：**

- 大模型 Function Calling 普及，AI 从「聊天」向「执行任务」演进；DeepSeek 等国产 API 成本持续下降（V3 约 2 元/百万 token 输入），有利于中小团队维持低成本 AI 服务。
- 国家统计局显示，截至 2024 年中国灵活就业人员超 2.4 亿；新就业形态劳动者约 6500 万，占二、三产业就业人员 11.78%；新型灵活就业招聘职位占比从 2019 年 8.4% 升至 2024 年 15.2%，临时性收入需求持续扩大。
- 央行《普惠金融指标分析报告》指出，低学历、农村居民、老年人等群体面临数字鸿沟；政府呼吁加强金融知识普及、开发贴近民生产品。精打细算面向该细分人群的生存规划工具，符合普惠金融与数字包容方向。

## 二、市场可行性分析

### 1、市场调查

**市场容量：**

- **灵活就业规模**：国家统计局数据，截至 2024 年中国灵活就业人员超 **2.4 亿人**；新就业形态劳动者约 6500 万，占二、三产业就业人员 11.78%。其中外卖骑手超 1000 万、职业主播达 3880 万。
- **个人债务规模**：2024 年末住户贷款余额约 82–83 万亿元；不含房贷的消费性贷款余额 20.43 万亿元，同比增长 5.8%。花呗/借呗等消费金融产品服务超 4 亿用户，逾 60% 来自三四线及以下城市，逾期协商、延期还款、债务管理需求旺盛。
- **网络招聘/兼职市场**：2024 年网络招聘行业规模约 **183 亿元**，同比增 1.6%；预计 2025–2027 年年均增速约 6.7%。中国灵活用工渗透率约 1%，远低于美国（10%）、日本（4%）、欧洲（5%），增长空间大。

### 4、产品定位与用户生命周期策略

**问题意识**：若产品仅定位「度过危机」，一旦用户债务缓解、收入稳定，即无继续使用理由——功能单一导致生存周期短、用户流失严重；新用户需持续拉新，获客成本高。**留存老用户远优于不断拉新**。

**应对策略**：坚持**垂直定位**（小而美），但不做「一次性工具」——同一核心「帮普通人管钱」，随用户人生阶段延伸服务：

| 阶段 | 用户状态 | 产品价值 |
|------|----------|----------|
| **阶段 1：危机中** | 钱紧、债务压力、撑不到发薪 | 生存天数、日预算、债务协商话术、跨平台机会聚合、今日可执行清单 |
| **阶段 2：稳定期** | 债务减轻、收入稳定 | 记账、预算控制、储蓄习惯养成、机会雷达持续推荐 |
| **阶段 3：积累期** | 有积蓄、想存钱 | 目标储蓄、简单理财意识培养、防冲动消费 |

**叙事主线**：「陪你从最难的时候，一直走到慢慢变好。」——功能聚焦、场景延伸，既保持垂直，又拉长用户生命周期与 LTV。

**不做**：不盲目拓展为「全平台资产聚合」（支付宝、银行、投资 App 汇总）——该品类已有随手记、挖财、蚂蚁财富等，竞争激烈且需对接机构、技术门槛高；精打细算优先深耕记账、预算、生存规划，待用户习惯与信任建立后再考虑轻量资产概览。

## 七、产品心智与关键文案

精打细算 Pro 的核心定位不是记账工具，也不是招聘平台，而是**穷人在钱紧时刻第一个想起的数字化同伴**——即「紧急出口」。本节将产品心智落地为可执行的文案对照，使评审与用户能直观感知差异。

### 1、「紧急出口」的定义

- **不是**：记账工具、招聘信息聚合、理财 App
- **是**：穷人在钱紧、债务压力、想搞副业时，**第一个想起的数字化同伴**
- **留存指标**：不看 DAU，看「关键时刻唤醒率」——用户每次钱紧时是否第一个打开你
- **付费逻辑**：不是「低价走量」，是「省/赚分润」——9.9 元帮他省 45 元罚息，价值锚定成立

### 2、三个关键场景的文案对照表

| 场景 | 改前（功能描述） | 改后（紧急出口心智） |
|------|------------------|----------------------|
| **生存概览** | 生存天数：5 天<br>危险等级：红色 | 生存天数：5 天<br>危险等级：红色<br>**这 5 天怎么过？ → 今日可执行清单已生成** |
| **机会雷达** | 机会雷达<br>兼职 · 零工 · 变现 | 机会雷达<br>**今天能赚到的钱**<br>「你适合的」根据你的技能为你筛选… |
| **债务协商** | 债务谈判官<br>生成协商话术 | **花呗逾期一天罚息约 1.5 元，这杯奶茶钱你能省**<br>债务谈判<br>打这个电话之前，先让我教你两句 |

### 3、为什么不抄大厂

| 维度 | 大厂 | 精打细算 |
|------|------|----------|
| 产品形态 | 做**功能**：页面工整、流程标准、用完即走 | 做**陪伴**：懂你这几天真的难，推荐的是「附近日结、中午 12 块怎么吃」 |
| 留存指标 | DAU、月活 | **关键时刻唤醒率**：钱紧时第一个想起你 |
| 定价逻辑 | 用户「收入」的一部分 | 用户「省/赚」的分润——9.9 帮他省 45，他付 |
| 护城河 | 流量、品牌、资本 | **创始人的真实经历淬炼出的决策语感**——大厂 PM 月薪 5 万，抄不走「真的穷过」的权重分配 |

**结论**：精打细算的对手不是阿里、美团，是「用户根本不记得你」。让用户被记住的方式，不是烧钱投广告，是：**在他最难的时候帮过他一次；在他下次难的时候，能第一时间找到你。**

## 附录 B：产品功能清单（基于当前代码）

### 核心模块

1. **生存数据录入**：存款、现金、资产、房租、伙食、交通、收入、发薪日、债务、技能标签
2. **生存概览**：生存天数、危险等级、可用资金、月支出、日预算、距发薪、账单提醒

4. **机会雷达**：后端实时聚合 API 对接实习僧/聚合数据/58同城等开放平台；分类筛选（打折、兼职、零工、变现、薅羊毛、悬赏）；未配置 API 时降级为 AI 扫描 + 本地兜底数据（详见 `docs/机会雷达实时数据配置.md`）

- 前端：HTML5 + CSS3 + JavaScript，PWA，橙白配色体系
- AI：DeepSeek API，Function Calling
- 数据：localStorage（离线）；可选 Node.js 后端 + JSON 存储（云端同步）
- 机会聚合：Vercel Serverless `/api/opportunities/search` 或 Node 路由，对接实习僧/聚合数据/58同城开放 API
- 认证：手机号验证码、微信扫码登录
- 部署：静态托管（Vercel）+ 可选 Serverless API；可选 Node 后端自托管
